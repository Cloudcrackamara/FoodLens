# FoodLens database schema

Describes the tables created by migrations `0002_initial_schema` and `0003_batch_scan` (models in `backend/app/models/`). Diagram: [`ERD.mmd`](ERD.mmd). Reasons for each choice: [`DECISIONS.md`](DECISIONS.md) D17–D30.

Migrations are the source of truth. If this file and the database disagree, the database wins and this file must be updated.

## Conventions

| Convention | Rule |
|---|---|
| Primary keys | UUID v4, named `<entity>_id`, generated by the application. |
| Enums | Stored as `VARCHAR` with a `CHECK` constraint listing allowed values (`ck_<table>_<enum>`). Python enums live in `app/models/enums.py`. Adding a value needs a migration that replaces the check constraint. |
| Timestamps | `created_at` on every table. `updated_at` only on tables whose rows are edited. All `TIMESTAMP WITH TIME ZONE`, default `now()`. |
| Review columns | Reviewable tables share `reviewed_by_user_id`, `reviewed_at`, `review_note`, plus their own status enum. **Only admin services set these.** No API input schema may include them. |
| Claimed data | Company-asserted facts that FoodLens has not verified are prefixed `claimed_`. |
| Data mode | Credential and agency rows carry `data_mode`, which only allows `DEMO`. |
| Constraint names | `pk_`, `fk_`, `uq_`, `ix_`, `ck_` prefixes from the naming convention in `app/models/base.py`. |
| Payments | No payment, price, or checkout columns exist. A test enforces this. |

Rules marked **(DB)** are enforced by the database. Rules marked **(service)** must be enforced in `app/services/` and covered by tests in the phase that builds them.

## Identity

### `app_user`
A person who can sign in: admin, company owner, or representative. Consumers do not need accounts.

| Column | Notes |
|---|---|
| `email` | Unique **(DB)**. Stored lowercased **(service)**. |
| `password_hash` | bcrypt hash. Never returned by the API, never logged. |
| `is_admin` | Default `false`. Set only by seed/CLI, never through the API **(service)**. |
| `is_active` | Inactive users cannot sign in **(service)**. |

### `user_session`
Server-side session behind the httpOnly cookie. Revocable on logout.

| Column | Notes |
|---|---|
| `token_hash` | Hash of the cookie token, unique **(DB)**. The raw token is never stored. |
| `expires_at`, `revoked_at` | A session is valid only if not expired and not revoked **(service)**. |

No `updated_at`: the only change is setting `revoked_at`.

## Companies

### `company`
A manufacturer, wholesaler, or both.

| Group | Columns | Who sets them |
|---|---|---|
| Company-managed | `company_type`, `display_name`, `contact_email`, `contact_phone` | Company. Contact edits are logged in `audit_log` **(service)**. |
| Claimed (unverified) | `claimed_legal_name`, `claimed_business_identifier`, `claimed_address` | Company. Never shown as verified. |
| Review | `review_status` (`PENDING_REVIEW` default, `APPROVED`, `REJECTED`, `SUSPENDED`), `reviewed_by_user_id`, `reviewed_at`, `review_note` | Admin only **(service)**. |

Buyer (wholesaler) companies may order without approval. Only `APPROVED` seller companies appear in the directory **(service)**.

### `company_member`
Links a user to their company.

| Column | Notes |
|---|---|
| `user_id` | Unique: one company per user **(DB)**. |
| `role` | `OWNER` or `REPRESENTATIVE`. |
| `membership_status` | `ACTIVE` (default) or `INACTIVE`. Inactive members have no company access **(service)**. |
| `is_public_contact`, `public_title`, `public_phone`, `public_email` | Shown on the supplier page only when `is_public_contact` is true **(service)**. Login email is never exposed. |

### `supplier_location`
A physical site of a company, reviewed before it appears in the directory.

| Column | Notes |
|---|---|
| `contact_member_id` | Optional named contact; must be a member of the same company **(service)**. |
| `review_status` | `PENDING_REVIEW` default, `APPROVED`, `REJECTED`. Only `APPROVED` locations are listed **(service)**. |

## Catalogue and credentials

### `product`
| Column | Notes |
|---|---|
| `product_code` | Barcode or FoodLens code. Unique **(DB)**. |
| `label_information` | Free text from the label. |
| `status` | Products created by approved companies are `PUBLISHED` at once (D61). `DRAFT`, `PENDING_REVIEW`, `REJECTED`, `WITHDRAWN` remain available but are not used by the current workflow. Published products change only through a change notice **(service)**. Only `PUBLISHED` products of approved companies are visible to lookup **(service)**. |

### `product_batch`
| Column | Notes |
|---|---|
| `(product_id, batch_number)` | Unique together **(DB)**. The same batch number may exist on different products. |
| `expiry_date` | Must be on or after `production_date` when both are set **(DB)**. A past expiry gives lookup result `BATCH_EXPIRED` **(service)**. |
| `qr_token` | Optional, unique, opaque. Not secret and not proof of authenticity. |
| `review_status` | Batches created by approved companies are `APPROVED` with no reviewer, meaning "published by the company" (D61-D62). Pending and rejected batches are invisible to lookup (`BATCH_NOT_FOUND`) **(service)**. |

### `regulatory_agency`
Simulated issuer and scheme, e.g. "NAFDAC (simulated)" / "Food product registration (demo)". `(name, scheme)` unique **(DB)**. `data_mode` is always `DEMO` **(DB)**.

### `credential_record`
Product-level credential. Never presented as a batch test or batch certificate.

| Column | Notes |
|---|---|
| `(agency_id, reference_number)` | Unique together **(DB)**. Seed references start with `DEMO-`. |
| `status` | `ACTIVE` or `INACTIVE` as stored in the demo record. "Expired" is computed from `valid_until`, never stored **(service)**. |
| `valid_until` | On or after `valid_from` when both set **(DB)**. |
| `data_mode` | Always `DEMO` **(DB)**. |
| `provenance`, `checked_on` | Where the demo record came from and when it was last checked. |
| `submitted_by_user_id` | Company user who entered it; null for seeded rows. Company-entered credentials are claims with fixed provenance text, stored `INACTIVE` until an admin approval sets them `ACTIVE` (D63, D67). |
| `review_status` | `PENDING_REVIEW` default. Pending credentials are hidden from lookup **(service)**. |

## Changes, announcements, and audit

### `change_notice`
A request to change published data. Nothing published changes until an admin approves.

| Column | Notes |
|---|---|
| `product_id`, `batch_id`, `credential_id`, `location_id` | Exactly one is set **(DB)**, and it must exist **(DB)**. Target must belong to `company_id` **(service)**. |
| `change_type` | `PACKAGING`, `LABEL`, `PRODUCT_DETAILS`, `BATCH_DETAILS`, `CREDENTIAL_DETAILS`, `LOCATION_DETAILS`, `OTHER`. |
| `review_status` | `PENDING_REVIEW` (default), `CLARIFICATION_REQUESTED`, `APPROVED`, `REJECTED`. Company reply to clarification returns it to `PENDING_REVIEW`. Submitter cannot approve **(service)**. |

### `change_notice_field`
One proposed field change. Append-only (no `updated_at`).

| Column | Notes |
|---|---|
| `(notice_id, field_name)` | Unique together **(DB)**. |
| `current_value` | Snapshot when submitted, shown in the admin diff. |
| `proposed_value` | New value; validated before it is applied **(service)**. |
| `applied_old_value` | Value actually replaced, set once on approval **(service)**. |

### `notice_attachment`
Supporting document or image. Append-only.

| Column | Notes |
|---|---|
| `mime_type` | `application/pdf`, `image/png`, `image/jpeg` **(DB)**. Content sniffing and extension checks **(service)**. |
| `size_bytes` | 1 byte to 5 MB **(DB)**. |
| `storage_key` | Random 32-hex key, unique **(DB)**; the file is stored at `UPLOAD_DIR/<key>` (default `backend/storage/notices`, git-ignored). Never a public URL; only admins and the owning company can download **(service)**. |

### `product_announcement`
Company pop-up message ("POPs"), e.g. "New packaging from March 2027".

- Goes live without review (`status` `LIVE` by default), only for approved companies; text with the whole words "safe" or "unsafe" is refused; counterfeit warnings are allowed (D77) **(service)**. `image_storage_key` is not used yet.
- Shown on lookup labelled "Message from the company — not reviewed by FoodLens" **(frontend + service)**.
- Never changes product data.
- Admin may set `HIDDEN`, recording `hidden_by_user_id` and `hidden_at` **(service)**.

### `audit_log`
Append-only history of meaningful changes: who (`actor_user_id`, null for system), what (`entity_type`, `entity_id`, `action`), and `old_values` / `new_values` as JSONB. Never contains passwords, tokens, or unneeded personal data **(service)**.

## Orders

### `wholesale_order`
An order **request**. No payment fields.

| Column | Notes |
|---|---|
| `buyer_company_id`, `seller_company_id` | Must differ **(DB)**. Seller must be approved **(service)**. |
| `pickup_location_id` | Optional; must be an approved location of the seller **(service)**. |
| `status` | `SUBMITTED` (default) → `ACCEPTED` / `DECLINED`; `ACCEPTED` → `FULFILLED`; buyer may `CANCELLED` while `SUBMITTED` **(service)**. Only the seller accepts or declines **(service)**. |
| `buyer_note`, `seller_note` | Free-text replies. |

### `order_line`
`quantity` > 0 **(DB)**, `NUMERIC(12,3)`. Product must be a published product of the seller **(service)**. Not edited after submission (no `updated_at`).

### `order_batch_allocation`
Records which batch fulfilled a line. `allocated_quantity` > 0 **(DB)**. Batch must belong to the line's product **(service)**.

## Lookups

### `batch_scan`
Anonymised log of consumer lookups (D46). Append-only. Written by `POST /api/lookups/batch`.

| Column | Notes |
|---|---|
| `input_product_code`, `input_batch_number` | Normalised input (trimmed, upper-cased, max 64 characters). |
| `matched_batch_id` | Batch the lookup resolved to, or null (not found, mismatch on product code, insufficient input). |
| `result` | One of the six lookup states **(DB)**. |

There is deliberately **no** user, session, IP address, user agent, or location column; a test enforces the exact column list.

## Working with migrations

```bash
cd backend
uv run alembic revision --autogenerate -m "describe change"   # after editing models
uv run alembic upgrade head
uv run alembic check                                          # fails if models and migrations differ
```

`alembic/env.py` renders enum columns as `sa.String` and keeps a single convention-named check constraint per enum, avoiding duplicates. Always read a generated migration before applying it. The test suite rebuilds `foodlens_test` from the migrations on every run and runs `alembic check`.
